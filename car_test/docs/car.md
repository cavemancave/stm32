# 两轮差速小车（速度环）—— 使用与原理

> 返回 [README](../README.md)。上位机协议层见 `tools/proto.py`，小车脚本见 `tools/car.py`。

小车底盘就是“两台电机 + 一条总线”，控制目标是**让轮子以给定转速一直转**。

## 电机以哪个环运行？—— 轮子用**速度环（0x02）**

| 环 | 0x64 给定值的含义 | 对“轮子”合适吗 |
| --- | --- | --- |
| 开环 `0x00` | 电压 | ❌ 完全没闭环，负载一变转速就飞 |
| 电流环 `0x01`（使能后的默认） | 力矩（±32767 ↔ ±4A） | ❌ 给的是力气不是转速：左右轮负载不一样就跑不直，上坡/压地毯会掉速，要定速得自己再做一套速度 PID |
| **速度环 `0x02`** | **转速（±3800 ↔ ±380rpm，1 单位 = 0.1rpm）** | ✅ **就是它**：电机内部自己闭环，给多少 rpm 就转多少 rpm，左右轮给一样的值就能走直；给 0 就是停 |
| 位置环 `0x03` | 目标角度（0~32767 ↔ 0~360°） | ❌ 给定值是“某一圈里的一个角度”，而且**按最短路径**走、接近目标时慢慢爬（实测 90° 要 1.7~2s 才停稳）。只适合“转到位就停”的关节（比如机械臂/云台），轮子会走一小段就停 |

所以：**小车用速度环，位置环留给机械臂那种“转到位”的场合**（`motor.py posloop/movepos/movedeg` 用它）。

差速底盘的两个自由度，用速度环表达起来非常直接：

| 动作 | 左轮 | 右轮 |
| --- | --- | --- |
| 直行 | `+v` | `+v` |
| 后退 | `-v` | `-v` |
| 原地左转 | `-v` | `+v` |
| 边走边拐 | 慢一点 | 快一点 |

（注意：位置环做不到“一直转”这件事 —— 位置值一圈是 0~32767 且 `32767 ≡ 0`，
发个大数值它只会按最短路径走到那个角度就停。）

## 用命令控制（`tools/car.py`）

`tools/car.py` 是给小车搭的测试框架，跑在 `proto.py` 的协议层上面。串口**不用写**：
系统上只有一个 USB 串口时脚本自己用它（用了哪个会打一行提示），要换就 `--port`
（写在子命令后面也行）或设环境变量 `CAR_PORT`：

```bash
python tools/car.py setup                                  # ① 上电 + 两台使能 + 切速度环
python tools/car.py status                                 #    两台在什么模式/位置/里程/故障码
python tools/car.py spin --motor 1 --rpm 20 --seconds 2     # ② 只让 1 号机 20rpm 转 2 秒
python tools/car.py spin --motor 2 --rpm -20 --seconds 2    #    只让 2 号机反着转
python tools/car.py watch --seconds 5                       #    看两台实际转速（编码器差分算的）
python tools/car.py drive --left 20 --right 20 --seconds 3  # ③ 两轮一起（按映射）
python tools/car.py stop                                    # ④ 停车
python tools/car.py stop --disable                          #    失能（不碰电源）
python tools/car.py stop --disable --poweroff               #    收工：失能 + 断电机电源
```

- `stop` 的三件事**各自独立**（速度环里给了转速就会一直转，所以停车是第一步）：
  `stop` = 只给 0 转速；`--disable` = 再失能（不碰电源，还能读状态）；`--poweroff` = 再断 PC14。

- **`setup` / `spin` / `drive` 都必须在同一个进程里自己收尾**：速度环下给了转速电机就会
  一直转，所以每个动作都是“给转速 → 等 → 一定给 0 停下”，Ctrl+C 也会在 `finally` 里停。
  但**第一次测试请把轮子架空、手别离开电源开关**。
- `setup` 还会做两件“小车专用”的事：把**左轮是几台**告诉设备（里程差闭环要用，见下一节），
  并把 200 ms 状态轮询停掉（闭环自己会读位置，两边抢总线只会都变慢）。
- `drive`（两台一起）走的是**一条** DRIVE 命令 —— 设备侧背靠背发两条 `0x64`，
  两台起步差从 30~80 ms 降到 ~10 ms；`spin`（只动一台）走的是 `motor.py speed`。
- `spin` 结束会打里程/位置的变化 —— **正 rpm 时位置和里程该往正方向走**，反了说明这个
  电机的相序/映射要反（记到映射里就行）。
- `watch` 的转速是拿 `(里程 x 32768 + 位置)` 的差分算的（差分按最短路径折一下，处理
  位置翻圈）。给 20rpm、`watch` 里读到 ±20 上下，说明速度环在工作、编码器刻度也对。

## 先搞清楚哪台电机是左轮（`car.py id`）

**“左” = 从车尾看着车头方向时的左手边**（驾驶员左手边）。台架上还没装车、或者不确定
接线顺序时：

```bash
python tools/car.py id              # 依次点动两台，然后问你是哪边轮子动了
```

它会：上电 + 两台切速度环 → **电机1 正转 1.5 s（停一下）→ 电机2 正转 1.5 s** → 停下来
**逐台**问两个问题（“电机N 转的时候是哪一侧的轮子动了” + “那侧轮子是往前还是往后”），
然后把结果写进 `tools/car_map.json`：

```json
{ "left": 2, "right": 1, "invert_left": false, "invert_right": true }
```

`invert_xxx = true` 的含义是「那台电机**给正 rpm 时是把车往后推**的」，`drive` 会自动取反 ——
**所以两台电机是镜像装的（一个正转往前、一个正转往后）不用改接线，改这个文件就行。**
不想跑交互提问就手写，还带 `--no-invert-xxx` 可以取消反向：

```bash
python tools/car.py map --left 2 --right 1 --invert-right     # 左轮=电机2、右轮=电机1（要反向）
python tools/car.py map --left 1 --right 2 --no-invert-left   # 改回来
```

⚠ 左右是以**站在车尾、朝车头看**为准的。定完映射先验两条（车架空或留出两米）：

```bash
python tools/car.py drive --left 20 --right 20 --seconds 1.5   # 该往车头方向直走
python tools/car.py drive --left 20 --right -20 --seconds 1.5  # 该原地左转（车头转向左边）
```

- 直行**往后走** → 两侧的 `invert` 都要反过来（`map --invert-left --invert-right`，
  或者从“两边都反”改成“两边都不反”用 `--no-invert-left --no-invert-right`）；
- 直行对、但原地转**转反了** → 说明左右认反了，把 `--left/--right` 对调、两个 `invert` 也跟着对调
  （例如 `map --left 1 --right 2 --invert-left --no-invert-right`）。

2026-09-22 那台车实测：**电机1 → 右轮，正 rpm 往后；电机2 → 左轮，正 rpm 往前**，
所以映射是 `{"left": 2, "right": 1, "invert_left": false, "invert_right": true}`（两台电机是
镜像装的，所以有一侧必须反向 —— 这是正常的，不用改接线）。

映射定了之后，`drive --left 20 --right 20` 应该**直着走**、`drive --left 20 --right -20`
应该**原地转**。这两条对不上就说明左/右或者方向记错了，回 `id` 重来。

## 键盘遥控（`tools/car.py teleop`）—— 按住就走，松手就停

```bash
python tools/car.py teleop --speed 30        # w/a/s/d 前后左右，空格急停，q 退出
```

| 键 | 动作 |
| --- | --- |
| `w` / `s` | 前进 / 后退（两轮同速） |
| `a` / `d` | 原地左转 / 原地右转（一正一负） |
| `w`+`a`、`w`+`d` | 一边前进一边拐（按键可组合，按住不放就一直是那个动作） |
| `空格` | 急停（按住期间一直给 0） |
| `q` | 退出（退出前会停车） |

**“松手就停”在终端里没有天然的事件**：终端只在**按下**（和自动重复）时发字符，**松开什么都不发**。
所以脚本两条路都备着，跑起来时会打印用的是哪一种：

| 模式 | 怎么工作 | 用在哪些终端 |
| --- | --- | --- |
| **kitty 键盘协议**（`CSI > 10 u`） | 按下/重复/抬起三个事件都带上类型，抬起**立刻**停 | VS Code 终端、kitty、wezterm 等 |
| **自动重复超时推断** | 一直按着的话终端会一直重复发那个字母，超过 `--release-ms`（默认 250ms）没再收到就算松手 | 不支持上面协议的终端 |

另外还有**看门狗**兜底：每条 DRIVE 命令自带“超过 `--watchdog-ms`（默认 400 ms）没收到新命令
就把两台停掉”。所以松手、无线断、模块掉电、笔记本睡死，车都会自己停，而不是指望最后那条
stop 命令发得出去。（这也**顺便把“电机断联保护”做掉了**，而且比开 `0xA0/0x10` 那套更好使：
那是电机自己的 3 秒计时，我们这里 400 ms 就停。）

- 发送频率默认 **20 Hz**（`--rate`，即每 50 ms 一条命令）；方向反了回 `car.py id` 重认映射。
- 车停着的时候脚本**不再刷命令**（目标已经是 0，不需要心跳），按第一个键时会立刻发。
- 退出时想顺手收工：`--disable` 失能、`--poweroff` 断电机电源（PC14），两个开关独立，
  要收工就都写（等同 `car.py stop --disable --poweroff`）。
- ⚠ 第一次先架空 / 用 `--speed 15` 试。

## 走直线：里程差闭环（在设备侧跑，25 ms 一拍）

两台电机**各自**的速度环给同样的给定值，转速并不会真的相等（环路静差、轮径、摩擦、地面都不一样），
所以开环差速“跑两米还行、跑十米一定歪”。这一版把“走直线”做成**车级闭环**，放在设备里：

```
每 25 ms：读两台 0x74 的位置 → 增量之差 (Δs_左 − Δs_右) → 积分（带泄漏）→ trim
          v_左 = 基准_左 − trim ,  v_右 = 基准_右 + trim     （只在变化 ≥1 个单位时才发 0x64）
```

- **为什么闭环放设备侧**：上位机每拍都要过一趟无线（10~30 ms 抖动），闭环会被链路抖死；
  设备侧本来就在总线旁边。一拍 = 2×`0x74` + 2×`0x64` ≈ 24 ms（10 字节帧 @38400 单程 2.6 ms），
  占空比 ~50%，放得下。
- 全是**整数定点**（不用浮点）：`trim = e/55`（546 计数 ≈ 10 秒的 0.1rpm 差 → 补 10 个 0.1rpm），
  积分泄漏 `e -= e/64`（时间常数 ≈1.6 s），输出限幅 ±120（±12 rpm）。
- ⚠ 位置**只用“最短路径增量”累加**，不用 `0x74` 的里程字段 —— 里程在位置过零点时会掉一整圈
  （见 `motor_drive.c` 里 `MotorDrive_ShortestDiff` 的注释）。
- **只在“直行类”动作下积分**（两侧同号，且速度差 ≤ 快的那侧的 1/4）：转圈/明显走弧时航向本来就
  在变，拿里程差去修会跟驾驶指令打架，所以那两种情况下自动停积分并把 trim 归零。
- 顺带把**起步差**也补掉了：以前“先动的那侧”多走的那点，会被积分项在随后 1~2 秒里还给另一侧。
- 看设备日志的 `[drive]` 行（1 Hz）：`rate` = 实测拍频、`e` = 里程差积分、`trim` = 当前修正量、
  `sent` = 真正发出去的（基准 ± trim）。`car.py drive` 收尾还会打两台各走了多少计数、以及
  **左−右** 差多少 —— 那就是这一段歪了多少。

## 固件侧加了什么（2026-09-22）

| 命令 | 码 | 干什么 |
| --- | --- | --- |
| `motor.py speedloop [--motor N]` | `0x0F` | 上电 → 使能 → `0xA0/0x02` 切速度环 → **用 `0x75/0x76` 复核模式值真是 0x02**（和切位置环同一个坑：不认这个模式的固件也会回一个合法的 `0xA1`，光看“有没有回帧”会误判）。回帧 `data` = 复核到的模式值 |
| `motor.py speed <±3800> [--motor N]` | `0x10` | 速度环给转速，**单位 0.1rpm**（`300` = 30.0rpm，负数反着转，`0` = 停）。回帧 `data` = 生效转速 |
| `motor.py accel <0..255> [--motor N]` | `0x11` | 速度环加速时间：每 1rpm 多少 ms（`0` 按 1 处理）。值越大起步越柔：`0→30rpm` 用 `accel x 30ms`。上电默认 **10**（0.3 s 起） |
| `motor.py drive <pair> --motor <wd>` | `0x12` | **两台一起走**：`arg` = `pair_pack(电机1, 电机2)`（各 0.1rpm 带符号，全 0 = 停车），第 6 个字节 = **看门狗超时**（单位 50 ms，0 = 不启用）。设备侧**背靠背**发两条 `0x64`；回帧 `data` = 原样回两个基准、`data2` = 看门狗 ms |
| `motor.py trim <0｜1｜2>` | `0x13` | 里程差闭环：`0` 关，`1`/`2` 开并且这个数就是“左轮”的电机序号。回帧 `data` = 开没开、`data2` = 左轮、`data3` = 当前 trim（0.1rpm） |

代码：`motor_ctrl.c` 里 `MotorCtrl_PrepareSpeedLoop / SetSpeed / SetSpeeds / GetAccel /
SetAccel`；**新模块** `Device/Motor/motor_drive.c`（闭环 + 看门狗任务，新 cmake 片段
`cmake/motor_drive.cmake`）；命令码在 `ota_layout.h` 往后接（`0x0F`~`0x13`，回帧结构没动，
老上位机不受影响）。

三个特意改的地方（都是实测逼出来的）：

1. **不再每条命令都查一次模式**（`motor.py speed` 原来先发一次 `0x75`）：改成内存里一个
   `s_in_speed_loop[]` 缓存，确认过一次就只发 `0x64`。⚠ 只有**会让电机离开速度环**的动作
   才清它：失能、断电/断电重启、进 OTA、切进位置环；另外 `0x64` 收不到合法 `0x65` 也会清
   （兜底：下次自动重新确认）。省掉的是一趟总线往返（~5 ms + HAL/队列开销），
   **而且这是“两台一起起步”的前提** —— 要是 `0x75` 夹在两条 `0x64` 中间，起步差就从 ~10 ms
   放大成“一次查询那么长”。
2. **`drive` 一条命令管两台，两条 `0x64` 背靠背**：实测两台最多差 30~80 ms（= 两次无线往返 +
   每台一次模式查询 + 上位机循环），低速时就是“先动的那侧把车拽歪一下”（20 rpm、60 mm 轮、
   轴距 130 mm 时 50 ms 差 ≈ 车头歪 1.4°）。合成一条之后只剩总线串行的 ~10 ms。
3. **`MotorPwr_OnAndSettle()` 不再每次都白等 500 ms**：它原来无条件延时，遥控 20 Hz 下每条
   命令都要等半秒（命令全堆在 otaSvc 任务里，实测会从 20 Hz 掉到 2 Hz）。现在**本来就是开着的
   就直接返回**，只有真的刚上电那一次才等。

⚠ **还没做的**：`trim` 只管“两台走一样多”，管不了**打滑**和**绝对航向**（轮子空转时里程差
是假的）。要更稳就得上板上的 BMI088（现在 `#if 0` 关着）：陀螺 Z 积分出 yaw 做航向保持，
输出还是这个差分项。另外速度环下电机“给了就一直转”，所以**别让车跑出急停开关范围**。

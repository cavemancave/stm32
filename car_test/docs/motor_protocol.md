# 电机 10 字节协议速查

> 返回 [README](../README.md)。驱动代码在 `Device/Motor/`，模块结构见 [`architecture.md`](architecture.md)。
> 规格书摘录见 [`specification.md`](specification.md)（源文件 `docs/M0603A_111_motor_specification_cn.pdf`）。

同一条 USART10 单总线上挂 2 台电机（ID1 / ID2），一问一答、固定 10 字节帧，
全部由无线命令控制（**固件里没有按键流程**）。

| 项目 | 值 |
| --- | --- |
| 串口 | **USART10**：PE2 = `USART10_RX`、PE3 = `USART10_TX`（AF4 / AF11，CubeMX 生成） |
| ⚠ TX 电平 | **PE3 必须配成开漏 `GPIO_MODE_AF_OD`**（CubeMX 里 PE3 的 Output type = Open Drain）。电机控制板是 **5V TTL** 单总线，高电平靠总线上拉；TX 用推挽时输出 MOS 管会常通，和 5V 上拉互相灌电流/把总线拉出错误电平 → **误发信号**。改代码没用，要在 CubeMX 里改（见 `usart.c` 的 `USART10_MspInit 1` 备注） |
| 参数 | **38400**, 8N1，一问一答，固定 **10 字节**帧 |
| 电机 ID | **ID1 / ID2 两台**（`motor_ids[] = {1U, 2U}`、`MOTOR_COUNT = 2U`）：ID 脚接地 = ID1、接高 = ID2，上电时锁存；两台**共用** PC14 那一路电机电源 |
| 成功判据 | **收到合法的 `0xA1` 回帧**（ID/功能码/CRC 都对）即算使能成功。⚠ 反馈的 `DATA[2]` 是**使能之后的实际模式**，不是回显 `0x08`：实测 ID1 回 `01 A1 01 00 00 00 00 00 00 E0`，模式值 `0x01` = 默认电流环 |
| 走位置环 | `motor.py posloop --motor N` 使能 + 切位置环（`0xA0/0x03`）。⚠ **手册 5.3 的模式表里没有位置环**，这个值来自厂家上位机工程（`docs/M0603A 系列直驱电机.bit` 的模式值下拉框里有「位置环 = 03」）和 `docs/M63A快捷指令集.cfg` 里的「电机1切换位置环」 |
| 确认模式 | 切完**再查一次模式**（`0x75`/`0x76`，紧跟切模式之后）：必须报 `0x03` 才算成功，否则打 `position loop NOT active (mode=0x..)` 并报错 —— 因为不认 0x03 的固件也会回一个合法的 `0xA1`，光看「有没有回帧」会误判 |
| 走位置 | `motor.py movepos <0..32767>` / `motor.py movedeg <0..359>`：位置环下 `0x64` 的给定值 = **目标位置**（0~32767 ↔ 0~360°）。位置环按**最短路径**走、接近目标时慢慢爬（实测 90° 要 1.7~2 s 才停稳），适合“转到位就停”的关节；**轮子不要用位置环**（见 [`car.md`](car.md)） |
| 失能 | `motor.py disable [--motor N]`：发 `0xA0/0x09`，把回帧的 `mode` 也打出来。失能只是「不使劲」，通信还在，所以 `motorPoll` 那一路的 0x74 轮询照旧；**电源不动**（PC14 归 0x08 管）。不指定电机 = 两台都失能，指定单台 = 只那一台 |
| 电源 | `motor.py pwoff` / `pwron` / `pwcycle`（= `0x08`，arg 0/1/2）：PC14 高有效、上电默认关断。`enable`/`speedloop`/`drive` 会自己先上电并等 500 ms；`disable` / 进 OTA 都不碰它 |
| 状态轮询 | 定时器每 **200 ms**（`MOTOR_CTRL_POLL_MS`）唤醒 `MotorCtrl_PollTask`，查一轮 `0x74`（等 `0x75`），打印**里程圈数、位置原始值（并换算成 0.1°）、故障码（按位译成 hall/overcurrent/stall/overtemp/link-loss/voltage，未知位写 other）** |
| 日志 | 打在**无线口 USART1**（921600）上，同时镜像到 UART7，见 [`hardware.md`](hardware.md) |

## 帧格式：`ID | 功能码 | DATA[2..8] | CRC8`

- 使能 `ID | 0xA0 | 0x08 0 0 0 0 0 0 | CRC8` → 反馈 `ID | 0xA1 | 模式值 0 0 0 0 0 0 | CRC8`
  （反馈的模式值是**切换后的实际模式**：发 0x08 使能后回的是 `0x01` 电流环，实测帧 `01 A1 01 00 00 00 00 00 00 E0`，CRC 已对过）
- 失能 `ID | 0xA0 | 0x09 0 0 0 0 0 0 | CRC8` → 反馈 `ID | 0xA1 | 模式值 0 0 0 0 0 0 | CRC8`
- 切位置环 `ID | 0xA0 | 0x03 0 0 0 0 0 0 | CRC8` → 反馈 `ID | 0xA1 | 0x03 0 0 0 0 0 0 | CRC8`
  （发送帧 CRC = `0xD9`，见 `docs/M63A快捷指令集.cfg`；0x03 不在手册 5.3 的模式表里）
- 走位置 `ID | 0x64 | 位置H 位置L 0 0 加速时间 刹车 0 | CRC8` → 反馈 `ID | 0x65 | 速度H 速度L 电流H 电流L 加速时间 温度 故障码 | CRC8`
  （位置值 0~32767 ↔ 0~360°，所以 0° = 0、90° = 8191，换算用 `Motor_AngleToPosition()`。
  参考 cfg 里的「电机1旋转转速30RPM」= `01 64 01 2C 00 00 00 00 00 A6`：`0x012C` = 300，
  而速度环范围是 ±3800 ↔ ±380rpm，所以这个数是 **rpm x 10**）
- 版本号查询 `ID | 0xFD | 0 0 0 0 0 0 0 | CRC8` → 反馈 `ID | 0xFE | 年 月 日 型号 软件版本 硬件版本 保留 | CRC8`
  （年字节是 20XX 的 XX，2021 年 = `0x15` = 十进制 21，所以日志里直接按十进制打）
- 状态查询 `ID | 0x74 | 0 0 0 0 0 0 0 | CRC8` → 反馈 `ID | 0x75 | 里程×4 位置H 位置L 故障码 | CRC8`

## 要点与坑

- ⚠ **CRC**：手册「CRC8 值」一节写明是 **CRC-8/MAXIM**（多项式 x⁸+x⁵+x⁴+1，反射，初值 0x00），
  所以代码里用反射形式的多项式 `0x8C`（`MOTOR_CRC8_POLY`）。校验值自查：对 `"123456789"`
  应得 `0xA1`。ID1 使能帧 = `01 A0 08 00 00 00 00 00 00 6F`。
- ⚠ **位置环（0x03）必须先确认真的切过去了**：`0xA0/0x03` 的反馈 `DATA[2]` 是**切换后的实际模式**，
  电机不认 0x03 时也会回一个合法的 `0xA1`（只是模式值不是 0x03），此时它还在电流环/速度环 ——
  再发 `0x64`（我们按“位置”给的 8191）就被当成电流/转速，**电机会一直转下去**。
  所以 `MotorCtrl_EnterPositionLoop()` 之后一律再用 `0x75/0x76` 复核模式值必须是 `0x03`
  （`MotorCtrl_PreparePositionLoop` / `OTA_CTRL_POS_LOOP` 都这么做）；不满足就打
  `position loop NOT active (mode=0x..)` 并拒绝后续动作。
  排查时看 `mode before switch` / `mode after switch` 下面那两行 `mode query (0x75)`，
  以及 `set mode (0xA0/0x03 ...)` 这行的 `mode=` 是多少
  （手册 5.3 的模式表里**没有** 0x03，它只出现在厂家上位机工程和 `docs/M63A快捷指令集.cfg`，
  所以不保证所有固件都认）。
- ⚠ **位置环停稳很慢**：一段 90° 大约要 **1.7~2 s** 才停稳，而且是**接近目标时慢慢爬过去**的
  （实测每 200 ms 还有 200~700 计数 = 1~4°/200ms，越接近越慢）。所以测量必须等它停稳 ——
  固定等 1.5 s 会读到“还差 8~13°”的中间值，**误判成“没走够”**。这不是分辨率问题：
  编码器 12 位、位置值 32768/圈 ≈ 0.011°。
- ⚠ **位置值是一圈，且 `32767 ≡ 0`**：直接命令 `32767` 等于“回到 0 点”，位置环按**最短路径**走，
  电机本来就停在 0° 附近 → 它压根不动（实测：命令 32767 后 `position` 一直停在 `61/65`）。
  **要走满一圈必须分步走**。
- ❓待确认：`0x65` 的“速度”字段在位置环下看着**不像速度**：电机停着时是 `-4`（≈0），
  而电机在动的那几次是 `7415 / 15410 / 23502`，和当时的**位置值**（`7424 / 15400 / 23493`）几乎一样。
  速度环下它才是真转速。要用这个字段得先单独验一下。
- 驱动里还实现了手册的其它命令：`Motor_QueryMode()`（0x75→0x76）、`Motor_Disable()`（0x09）。底层都走同一个 `Motor_Transaction()`。
- 排查：`rx=` **全 0** = 一个字节都没收到（没接线 / 没上电 / 波特率不对）；
  有数据但 `reply=NONE` = 帧对不上（CRC 或错位），把 raw 打出来比对。
